# 实现架构

`visionflow_protocol`：无第三方依赖的字节协议；队列和线程池为头文件模板。
`visionflow`：配置、结构化日志、JPEG 尺寸检查、算法工厂。
`vision_server`：Linux epoll 水平触发事件循环；`vision_cli`：本地 JPEG；
`vision_supervisor`：posix_spawn、signalfd、waitpid。

## 所有权与线程

网络线程独占监听 socket、连接表、接收状态、发送队列和网络统计。
连接用递增的 64 位 session token 标识，epoll 和任务都携带 token，绝不通过旧 fd 查找新连接。
工作线程只持有 Job 的 JPEG 和各自的处理器实例。使用 `cv::setNumThreads(0)` 关闭 OpenCV 内部并行，每个任务在调用线程处理。
结果通过有界队列交回网络线程，用 eventfd 唤醒。工作线程不写客户端 socket。

网络循环每次读取/写入最多 256 KiB、接入最多 32 个客户端，避免一个连接长时间独占。
离线待入队连接轮换优先级，最多等待一次 100ms 的事件循环轮询或工作完成通知。

## 内存与过载

任务、结果队列同时限制数量和字节。每连接只组装一个消息，先检查 24 字节头再分配消息体。
每连接未完成额度包括已入队、执行中、待发送响应；发送完毕才归还额度。
发送队列按仍持有的完整 buffer 计费，部分写不会提前释放预算。
同时设置 socket SO_SNDBUF；Linux 可能对该值加倍记账，仍不把内核缓冲当成用户态预算。

`offline`：满队列时在连接上保留一帧并暂停该连接读取；用 TCP 和客户端 window 控制后续积压。
`realtime`：淘汰全局队列最旧的尚未执行任务并返回 `dropped`，运行中任务不被取消。
相同连接达到额度时仍会暂停读取；本版本不是严格的每客户端公平调度器。
断线任务可能继续计算，结果在会话不存在时丢弃。

启动检查估算上限：客户端数 ×（最大 JPEG + 最大发送缓存）+ 任务字节预算 + 结果字节预算
+ 工作线程数 ×（最大像素数 × 32 + 最大 JPEG + 64 KiB）。
它是保守的配置审核估计，**不是操作系统强制 RSS 上限**，不包含所有 OpenCV、分配器、内核 socket 开销。
默认 640 MiB 的配置预算可处理最高 1920×1080 的图像。单边还限制为 4096。

JPEG SOF 在 OpenCV 解码前检查；只接受基线/渐进 8 位 Huffman JPEG；忽略 EXIF 旋转，保持结果坐标与发送像素一致。
图像算法使用灰度、高斯滤波、Canny。道路线段增加梯形 ROI、HoughLinesP、斜率过滤和线段数量上限。
接口返回坐标/边缘像素计数；网络不传回边缘图。离线工具可保存边缘预览图。

## 退出和异常

SIGINT/SIGTERM 在工作线程创建前屏蔽，由网络线程通过 signalfd 读取。
停止监听、停止读取新帧、关闭任务入口并排空已接受任务，同时继续发送结果。
达到宽限期后丢弃队列和连接；关闭结果队列唤醒可能阻塞的发布者，再 join 工作线程。
正在执行的 OpenCV 调用不能被安全强杀，因此宽限期不是进程退出的硬截止时间。
监管程序转发 SIGTERM，10 秒未退出则 SIGKILL，始终 waitpid 回收；不自动重启，不管理整个进程树。

线程任务边界捕获算法异常并返回请求错误；发布结果时的严重失败使主循环报告错误并退出。
启动失败或异常展开时先关闭结果队列，再 join，避免工作线程等待已停止的消费者。
监管程序使用标准输出/错误传递启动与退出信息，尚未实现独立状态管道。

## 局限

算法用于教学，不是自动驾驶感知系统，无曲线拟合、时序跟踪、遮挡恢复或识别准确率保证。
网络只支持 IPv4、可信本机/局域网，无 TLS 或认证。半关闭连接视为断开，客户端应保持双向连接直到读完结果。
可选 ONNX、动态库插件未实现；没有捏造历史调试记录或优化提升比例。
