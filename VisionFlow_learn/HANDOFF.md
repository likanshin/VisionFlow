- 服务端只接受一次连接、处理一张图片并回传一次响应，然后退出。再次使用客户端前须由学生重新启动服务端。
- 监听 fd 与 accept 返回的已连接 fd 是两个资源；后者用于收发。listen 的 backlog=1 不是“总共只处理一个请求”的原因。
- 请求：24 字节 VFLW 头 + 图片文件原始压缩字节；客户端固定 request_id=42，体非空且最多 16 MiB。
- 先收齐并校验头，再按合法长度分配并收齐体；decode 仅解释消息头，不执行网络接收。
- 服务端 cv::imdecode 后调用 `create_processor("lane_lines", 3)`；固定最多 3 条线段，不读取 CLI 的配置文件，所以 CLI 的 max_lines=2 不影响它。
- 响应：VFLW 头 + UTF-8 JSON，整条最多 64 KiB，即体最多 65512 字节；响应头及 JSON 沿用请求编号。
- 成功响应 type=2、status=ok；业务错误 type=3、status=error，code 为 invalid_image 或 processing_failed。
- 收头／协议校验／收体等失败由外层 catch 报告并结束；图片解码和处理失败可由内层 catch 构造错误 JSON，再尝试发送。
- 服务端成功完成响应发送流程返回 0，即使发送的是业务错误；客户端收到错误响应返回 1。发送正常返回不等于远端应用已经处理完毕。
- 服务端不写结果图片或 build/result.json。stdout 提示与 socket 回传的 JSON 是不同输出。
- 本课没有应用层超时、持续请求或多客户端处理；这些属于后续模块。
