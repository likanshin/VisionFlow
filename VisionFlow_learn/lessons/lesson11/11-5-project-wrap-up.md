## 1. 现在得到的是什么系统

当前学习工程实现了一条跨 Python 与 C++ 的图片处理链路，并将它扩展到本地视频的抽帧请求、结果记录和离线回放。

~~~mermaid
flowchart LR
    P["Python 图片／视频客户端"] -->|"VFLW 头 + JPEG"| R["C++ epoll 事件循环"]
    R -->|"图片任务"| Q["有界任务队列"]
    Q --> W["工作线程：图片处理"]
    W -->|"处理结果"| D["完成队列"]
    W -.->|"eventfd 唤醒"| R
    D -->|"取回结果"| R
    R -->|"VFLW 头 + JSON"| P
    P --> J["视频结果 JSONL"]
    J --> V["离线回放程序"]
    S["保留的源视频"] --> V
    V --> O["回放视频与 PNG"]
~~~

eventfd 表示需要处理完成通知，实际结果仍从完成队列取回；网络连接的收发由事件循环负责。这里的“视频服务”是客户端逐帧抽样并发送图片，不是服务端接收一个完整视频文件，也不是实时视频推流系统。

另有三类辅助入口：

- 进程监管器：启动直接子进程、请求停止、到期升级强杀并回收。
- 集成验证脚本：管理一轮自建服务端和客户端，检查业务产物。
- 性能观察脚本：向已有服务端发有限数量的并发请求，记录分类指标。

这些入口各有职责。11-3 集成验证直接管理本次服务端，没有再套旧监管器；11-4 测量脚本只向现有服务发请求，不负责启动或停止服务。

## 3. 关键数据如何关联

这张表用于查阅编号含义，不是要求重新答题。

| 标识 | 归属 | 用途与边界 |
| --- | --- | --- |
| fd | 当前进程的操作系统文件描述符表 | 执行 socket 操作；关闭后编号可被复用 |
| connection token | 服务端当前进程的连接管理 | 关联异步结果与仍存活的目标连接；不以旧 fd 直接寻找收件人 |
| request_id | 协议请求与响应 | 客户端检查消息头及 JSON 对应；不是跨所有运行的全局唯一 ID |
| frame_index | 源视频解码序列 | 定位结果应画在哪一帧，不等于请求编号 |
| record_pos | 回放程序的记录列表 | 指向下一条待匹配记录，与帧下标分开 |
| client_worker | 性能观察客户端 | 标识客户端工作循环，不等于 C++ 工作线程编号 |

记录目录也有不同格式：

- video_run_01.jsonl 与 e2e_01/video.jsonl 是视频结果，可以交给回放。
- perf_c*/requests.jsonl 是性能样本，不包含视频回放所需的完整字段。
- report.json 是整体报告，不是“一行一条视频结果”的 JSONL。
- 不同运行的 request_id 可以从相同数字重新开始，目录与来源信息承担运行间的区分。

## 5. 本次性能观察怎样表述才准确

| 并发上限 | ok / busy | 成功吞吐（请求/秒） | 成功平均（ms） | 成功 P95（ms） |
| --- | --- | --- | --- | --- |
| 1 | 60 / 0 | 173.50 | 5.743 | 6.777 |
| 2 | 60 / 0 | 296.68 | 6.673 | 10.655 |
| 6 | 20 / 40 | 347.83 | 11.586 | 14.977 |

可以说：

> 在同一输入 JPEG、每组五次预热和 60 次正式尝试的本地短闭环实验中，并发 2 相对并发 1 的成功吞吐约增加 71%，同时成功延迟上升；并发 6 有 40 次 busy，成功吞吐约 347.83 请求／秒。结果仅描述这次条件下的有限样本。

不要把 1043.50 个有效响应／秒写成成功图片处理吞吐，不把并发 6 的 57.5 毫秒整批时间当作成功处理 60 张图片的耗时，也不称为“稳定支持每秒 347 张图片”。

成功样本数为 60、60、20，批次时长均不足半秒。服务端 workers=2、queue=2、delay_ms=0 在本轮报告中是人工声明，不能说测量客户端已经自动验证这些配置。

## 6. 已实现的机制与当前边界

| 机制 | 当前具备的行为 | 没有据此得到的保证 |
| --- | --- | --- |
| 长度与数量限制 | 协议体长、连接数量和任务积压有边界 | 不等于解码像素与所有中间 Mat 的完整硬内存预算 |
| 超时 | 连接等待、子步骤和停止过程有各自等待限制 | 不等于算法可取消或整轮严格实时截止 |
| 优雅停止 | 停止入口、处理已有任务和响应，再回收线程 | 不保证父进程强杀、机器故障时正常执行清理 |
| 进程监管 | 管理直接子进程，TERM 后必要时升级 KILL 并回收 | 不等于管理任意后代树、自动重启或生产服务编排 |
| 离线回放 | 按帧匹配记录并输出固定帧率无音频视频 | 不证明检测精度、精确可变帧率时间轴或源视频未被替换 |
| 集成验证 | 固定素材上的顺序正常路径和产物检查 | 不覆盖所有错误分支、并发交错或长期稳定性 |
| 性能观察 | 分类延迟、成功吞吐、busy 比例与原始样本 | 不证明服务端内部瓶颈、稳态容量或生产性能目标 |

这些边界不是要求现在把项目全部扩展一遍，而是让“已经实现”和“还未证明”分得清楚。
