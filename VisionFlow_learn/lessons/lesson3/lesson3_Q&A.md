## 问题 1：高斯平滑是什么意思？

高斯平滑指用**邻域像素的加权平均**替换每个像素，权重按二维高斯分布分配——中心最大，向外递减。它在保留大尺度结构的同时抹掉高频细节，因为噪声主要藏在高频里。视觉效果像给图像做了轻微磨皮。

### 参数

```cpp
cv::GaussianBlur(gray, blurred, cv::Size(5, 5), 0);
```

| 参数 | 含义 |
| --- | --- |
| `gray` | 输入（单通道灰度图）|
| `blurred` | 输出 |
| `cv::Size(5, 5)` | 卷积核大小，5×5。核越大越模糊，通常用奇数 |
| `0` | `sigmaX = 0`，由核大小自动推算 σ（5×5 → σ≈1.1）|

5×5 核归一化后（权重和 = 1，保证整体亮度不变）：

```text
 1  2  4  2  1
 2  4  8  4  2
 4  8 16  8  4      ÷ 16
 2  4  8  4  2
 1  2  4  2  1
```

因为高斯核**可分离**（二维 = 两个一维卷积），OpenCV 实际执行一次横向 1D 加一次纵向 1D，复杂度从 O(n²) 降到 O(2n)。

### 为什么放在 Canny 之前

`cv::Canny` 本质是求梯度（一阶导数），求导会放大高频。原始图里一个单像素噪点，在梯度图上就是一条很强的假边缘。标准流程是：

```text
灰度 → 平滑（降噪）→ 求梯度（Canny）→ 边缘
```

先平滑再求导，等价于对图像做**高斯的一阶导数滤波**，是 Canny 理论上的标准做法。

### 代价

- **边缘定位变模糊**：丢掉的高频里也有真实边缘的锐度，核越大边缘越"胖"
- **弱边缘可能被抹掉**：细节和噪声尺度相近时，两者一起消失
- 5×5 加 σ≈1.1 是常见折中；噪声很重时才上 7×7
- 替代方案 `cv::medianBlur`（中值滤波）对**椒盐噪声**效果更好且不模糊边缘，因为它取中位数而非加权平均

## 问题 2：一块亮度完全均匀的纯白区域，其内部一定会被检测为边缘吗？为什么？

**不会。** 均匀区域内部恰恰是 Canny 最"看不上"的地方。但边界会——除非周围也是同样亮度的白。

### 原因：Canny 检测的是梯度，不是亮度

| 步骤 | 在均匀区域的取值 |
| --- | --- |
| ① 高斯平滑 | 均匀卷积均匀 → 仍是 255，不变 |
| ② Sobel 求梯度 | `Gx = 0, Gy = 0`（左右上下都一样，差分为 0）|
| ③ 梯度幅值 `M` | `M = 0` |
| ④ 非极大值抑制 | `M = 0`，无极大值可言，仍为 0 |
| ⑤ 双阈值 + 滞后 | `0 < 100`（低阈值）→ 直接丢弃 |

关键在第二步。Sobel 核本质是一次**中心差分**：

```text
Gx:  -1 0 1        Gy:  -1 -2 -1
     -2 0 2              0  0  0
     -1 0 1              1  2  1
```

纯白区域里一个像素和它右邻像素都是 255，差分 = 0，所以 `M = 0`，连弱边缘都算不上。**亮度本身完全不参与判断**，参与判断的只有"亮度变化的快慢"。

这也解释了为什么 Canny 输出是线条而不是色块：它没法告诉你"这里有一块白区域"，只能画出轮廓。

### 边界会被检测，但有前提

白色区域边缘上，梯度 = 4 × 亮度跳变（Sobel 权重绝对值之和为 4）。跳变 255 时 `M` 可达上千，远超 200，是强边缘。

但如果白色区域外面**也是纯白**，这个"区域"在图像上根本不存在边界——梯度处处为 0，Canny 输出一张全黑图。所以准确说法是：

- 均匀**且与周围无差异** → 什么都检测不到
- 均匀**但与周围有差异** → 只有边界被检测到，内部依然为空

### 什么情况下结论会破

"完全均匀"是理想假设，真实图像（尤其 `frame.jpg` 这种 JPEG）内部并不干净：

1. **传感器与压缩噪声**：JPEG 在强边缘附近有振铃效应，8×8 DCT 块边界也残留几个灰阶的起伏。幅度通常 ±3~5，经 Sobel 放大 4 倍约 20，仍低于低阈值 100——这正是**必须先高斯平滑**的原因。噪声幅度大到 ±15 以上时，不模糊直接 Canny 就会在白区内部炸出雪花状假边缘。
2. **光照渐变**：一片"看起来均匀"的白墙，实际可能从 252 缓慢降到 246。但相邻像素差不到 1，`M` 依然接近 0。**缓变不产生边缘，只有突变才会**——这正是边缘检测能忽略光照不均的原因。

## 问题 3：把两个阈值提高后，筛选会更严格还是更宽松？边缘像素更可能增加还是减少？

**更严格，边缘像素只会减少**——而且是**单调不增**：100/200 的结果一定是 50/150 结果的子集，不可能多出任何像素。

> 本课实测印证了这一点：仅把阈值由 50/150 改为 100/200，两次 `Edge pixels` 均为 2095。数量不变属于"减少或不变"的合法结果，因为新像素集合是旧集合的子集。

### 两个阈值分工不同

| 参数 | 角色 | 作用 |
| --- | --- | --- |
| `threshold1 = 100` | **准入线** | `M < 100` 直接出局，连参选资格都没有 |
| `threshold2 = 200` | **种子线** | `M > 200` 成为"强边缘"种子 |
| `100 < M ≤ 200` | **弱边缘候选** | 只有沿 8 邻域连到某个种子才被保留（滞后机制）|

于是"提高阈值"拆成两件事，方向完全一致：

- 抬高 `threshold1` → 淘汰线上移 → 候选像素集合**缩小**
- 抬高 `threshold2` → 种子变少 → 链条更容易断 → 能救活的弱边缘**变少**

两个集合都只减不增，最终输出必然是旧结果的子集。不存在"提高阈值反而检测出更多边缘"的情况。

### 换算成亮度差

Sobel 3×3 核对阶跃边缘的响应是相邻亮度差的 **4 倍**：

- `M > 100` ⟺ 相邻亮度跳变 **≳ 25 灰阶**
- `M > 200` ⟺ 跳变 **≳ 50 灰阶**

即：**亮度差小于约 25 的边界，现在完全看不见了。**

> 实现细节：默认 `L2gradient=false`，Canny 内部使用的是 `M = |Gx| + |Gy|` 这个 L1 范数，不是 `√(Gx²+Gy²)`，数值偏大，但量级一致。

### 代价：收益和损失不对称

**被清掉的（好事）**：`M` 落在 50~100 区间的**噪声和纹理**——草地、砖墙、布纹、JPEG 振铃。画面明显变干净。

**被误伤的（坏事）**：**低对比度的真实边界**——白物体贴在浅灰背景上、柔和阴影轮廓、远处失焦景物，`M` 可能只有几十。注意是"**整段消失**"而非"变淡"：一旦低于准入线，这段边界在输出里就不存在了。

**基本不受影响的**：强边缘。物体轮廓、文字、明暗交界处，`M` 常在数百到数千。

综合效果：**轮廓更干净、更连续，但细节变少，细弱结构可能整段断裂。**

### 三个容易踩的点

1. **交换参数位置没用**。OpenCV 源码里有 `if (low_thresh > high_thresh) std::swap(...)`，所以 `Canny(img, out, 200, 100)` 和 `(100, 200)` 结果完全一致。
2. **比例其实变了**。原来 `150/50 = 3:1`，现在 `200/100 = 2:1`，滞后带变窄。常用经验是 `high:low ≈ 2:1 ~ 3:1`，两组都合理——真正变严的原因是**绝对值翻倍**，不是比例。
3. **阈值和模糊是同一件事的两面**。Canny 的梯度是在**模糊之后**的图上算的。把 `GaussianBlur` 改成 7×7 或 σ=2，整图梯度幅值会被压低，同一组 `100/200` 会突然变得**过分**严格。调 σ 和调阈值不能独立看待。

### 更好的做法

手调阈值在不同曝光、不同场景下表现差异大。常见做法是**用图像自己的梯度分布定阈值**：

```text
low  = 0.66 * median(M)
high = 1.33 * median(M)
```

这样阈值随图像内容自适应，换张照片不用重新猜数。MATLAB 的 `edge(..., 'Canny')` 自动阈值走的就是这个路子；OpenCV 没有内置，需自己用 `cv::Sobel` 算出 `M` 再取中位数。

## 问题 4：`M = 130` 的候选像素，在两种情况下的命运？

**前提**：当前阈值为 100/200。

| 情况 | `M = 130` 像素的命运 | `edges` 中的值 |
| --- | --- | --- |
| ① 通过合格候选链连到 `M = 250` 的强边缘 | **保留** | 255 |
| ② 孤立，连不到任何强边缘 | **丢弃** | 0 |

两种情况里这个像素**自身的证据完全相同**（都是 `M = 130`，都落在 `[100, 200]` 内，都是合法候选）。唯一区别是**拓扑连接性**——它是否和某个强边缘属于同一结构。

> 这正是滞后（hysteresis）的含义：**判定标准不是"这个像素有多强"，而是"它是否和强边缘连成一片"。**

### 机制：滞后是怎么"灌"进去的

把它想成洪水填充：

1. 所有 `M > 200` 的像素标记为种子（情况①中 `M = 250` 的像素），压入栈
2. 弹出一个种子，扫描其 **8 邻域**，凡 `M > 100` 的像素**标记为边缘**并压入栈
3. 重复直到栈空
4. 结束后所有未被标记的像素——包括情况②的孤立像素——全部清零

第 2 步的传播是**传递闭包**：A 连 B、B 连 C，只要 A 是种子，C 也会被保留，哪怕 B 和 C 自己都很弱。链条上不需要每个像素都强，只需每个都**过得了 100 这条准入线**。

### 三个会改变结果的细节

1. **链条中间不能有断点**。若链上某个像素是 `M = 95`（低于准入线），链就**断了**，`M = 130` 退化成情况②被丢弃。这精确解释了：**低阈值决定边缘的连续性，高阈值决定边缘的存在性**。
2. **用 8 邻域，不是 4 邻域**。对角方向也算连通。4 连通下斜向边缘会碎成点，8 连通下不会。
3. **种子无条件保留**。`M = 250` 的像素不需要连接任何人，它自己就是源头。

### 对比：如果改用单纯阈值化

若改用 `cv::threshold(mag, edges, 100, 255, THRESH_BINARY)`，**情况①和②都会被保留**，因为两者的 `M` 都过了 100。结果是一张布满碎屑的图——真实边缘周围散落大量孤立的弱响应点，它们和边缘毫无关系，只是恰好梯度超过 100。

滞后机制正是用来干掉这些碎屑的：**只有"附着在强边缘上"的弱响应才算数**。所以 Canny 的输出远比单纯阈值化干净，同时边缘又比"只用高阈值 200"完整得多——高阈值单独用会让边缘断成一段段，低阈值把它们重新接起来。

### 实践上的坑

被保留的弱边缘在 `edges` 里**也是 255**，和 `M = 250` 的种子一样白。Canny 的输出是**二值图，不携带梯度强度信息**——所以从 `build/edges.png` 里**分不出哪些是真强边缘，哪些是靠连通性救回来的弱边缘**。

这个区分在很多场景下有用（排序边缘重要性、只保留强边缘做形状匹配）。要保留它，需自己算一遍 `cv::Sobel` 拿到梯度幅值矩阵，不要只依赖 Canny 的输出。
