## 学习约定

- 每次推进一个完整知识点，例如命令行参数、JSON、配置或日志。一个知识点对应一份讲义，内部用小节分步骤，不把每个选项或微小修改拆成独立小课。
- 引入新知识点前，先询问学生是否已了解；学生确认已掌握时，跳过对应教学和理解检查，老师说明改动后直接完成该步代码实现，无需再次请求授权。部分了解时，只讲解尚不熟悉的内容。
- 对尚未掌握的内容，按照“目标 → 原理 → 小步实现 → 运行观察 → 动手练习 → 理解检查”进行。
- 如果学生仅了解概念但没有实现经验，安排项目内的小步实践，由学生编写和运行，不直接按“已掌握”跳过。
- 老师负责维护 `lessons/` 讲义、`samples/` 素材、`README.md` 进度、`CMakeLists.txt` 构建配置等辅助文件，并解释相关改动。
- 课程资料按 `lessons/lessonN/` 分目录存放；同一模块的各知识点讲义和问答记录放在对应目录。已完成的旧课不为统一形式而重做。
- 尚未掌握的主要代码逻辑由学生编写，老师提供示例和指导；学生明确表示已掌握并跳过的步骤，由老师直接修改主要代码文件。
- 讲义必须给出具体修改文件、可定位的原代码或插入位置、需要写入的代码及其作用，不能只列实现要求；学生按照讲义亲手修改源码并执行课程实践。
- 课程实践由学生执行，包括配置、构建、运行程序和测试；老师不代为运行。老师可以读取文件、检查代码和维护辅助资料。
- 学生反馈输出或报错后，老师帮助分析；遇到不理解的概念就在当前课补充。
- 对需要教学的内容，学生完成练习并解释关键概念、确认理解后才继续；学生明确表示已掌握的内容可按前述约定跳过。“继续任务”本身不代表已经掌握当前模块。
- 尚未学习的模块只列出路线，不提前实现。
- 学习工程中面向使用者的提示统一使用简体中文，包括命令行帮助、统计输出、保存提示、日志消息和自定义错误提示；后续新增代码及讲义中的代码示例也遵守此约定。命令行选项、配置与 JSON 字段名、处理器名称、日志等级、阶段标识等程序接口保留原样，第三方库产生的原始错误详情保留，便于排查问题。

## 项目要完成什么

```text
Python 视频客户端 → JPEG 图片 → TCP → C++ 服务端
                                      ↓
                                 图像处理任务
                                      ↓
Python 显示／记录 ← JSON 结果 ← TCP ← 处理结果
         ↓
       离线回放
```

先完成不涉及网络的本地图片处理工具，再逐步加入协议、网络和并发。
